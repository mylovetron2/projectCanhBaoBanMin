Windows Hardware Flow

Native bridge nhận dữ liệu phần cứng qua NI-DAQmx

Trên Windows, ứng dụng Flutter không cần chạy file cdaq9181_console.exe để lấy dữ liệu từ cDAQ-9181. Thay vào đó, app gọi native bridge C++ trong chính Windows runner, bridge này nạp nicaiu.dll của NI-DAQmx runtime, tạo task DAQ, đọc mẫu analog từ phần cứng, rồi stream kết quả về Flutter qua EventChannel.

Flutter MethodChannel Windows native bridge NI-DAQmx runtime DAQmxReadAnalogF64 EventChannel

Kết luận ngắn

Nếu đang chạy app trên Windows, việc thiếu cdaq9181_console.exe không tự động làm mất dữ liệu phần cứng. Điều app thực sự cần là:

  1. Windows runner có native bridge C++.
  2. Máy đã cài NI-DAQmx runtime x64.
  3. Tham số channel đúng với thiết bị thật.
  4. App đang ở chế độ bridge, không phải demo.

nicaiu.dll là gì

nicaiu.dll là thư viện runtime chính của NI-DAQmx trên Windows. DLL này chứa các hàm như DAQmxCreateTask, DAQmxStartTask, DAQmxReadAnalogF64, DAQmxGetSysDevNames.

Native bridge không hard-link trực tiếp các hàm đó ở link time, mà tự nạp DLL lúc chạy.

Cách native bridge nạp NI-DAQmx runtime

  1. Code vẫn include NIDAQmx.h để lấy kiểu dữ liệu, hằng số, và suy ra kiểu function pointer an toàn.
  2. Khi Flutter gọi startBridge, bridge chạy api.Load(error).
  3. LoadLibraryW(L"nicaiu.dll") được gọi để nạp runtime NI-DAQmx vào process của app.
  4. Sau đó bridge dùng GetProcAddress để resolve địa chỉ thật của từng hàm DAQmx cần dùng.
  5. Nếu thiếu DLL hoặc thiếu symbol, bridge trả lỗi ngay thay vì làm app crash lúc khởi động. 
module = ::LoadLibraryW(L"nicaiu.dll");
if (module == nullptr) {
  *error = "Khong the nap nicaiu.dll. Can cai NI-DAQmx runtime x64 tren may Windows.";
  return false;
}

return Resolve("DAQmxCreateTask", &create_task, error) &&
       Resolve("DAQmxStartTask", &start_task, error) &&
       Resolve("DAQmxReadAnalogF64", &read_analog_f64, error);
Cách làm này giúp app vẫn mở được ngay cả khi máy chưa cài NI-DAQmx. Lỗi chỉ xuất hiện khi người dùng thật sự bấm kết nối phần cứng.

Vì sao không link trực tiếp NIDAQmx.lib

Cách làm Hệ quả
Link trực tiếp lúc build App có thể không khởi động được nếu máy chạy thiếu runtime NI-DAQmx.
Load DLL động lúc chạy App vẫn mở bình thường, chỉ fail ở chức năng bridge nếu thiếu runtime.

Luồng nhận dữ liệu từ phần cứng trên Windows

  1. Flutter gọi MethodChannel để yêu cầu start bridge.
  2. Windows runner parse args như sample rate, samples per read, min, max, ai-mode, channel.
  3. Bridge quét thiết bị bằng DAQmxGetSysDevNames.
  4. Bridge tạo task bằng DAQmxCreateTask.
  5. Bridge tạo kênh đo bằng DAQmxCreateAIVoltageChan hoặc DAQmxCreateAIAccelChan.
  6. Bridge cấu hình clock lấy mẫu bằng DAQmxCfgSampClkTiming.
  7. Bridge start task bằng DAQmxStartTask.
  8. Bridge đọc block dữ liệu thật bằng DAQmxReadAnalogF64.
  9. Bridge xử lý dữ liệu thành RMS, FFT, waveform.
  10. Bridge đẩy các dòng DATA_MULTI, FFT_MULTI, WAVE_MULTI về Flutter qua EventChannel.

Bridge tạo và đọc task DAQ như thế nào

DAQMX_ERR_CHK(api.create_task("", &task_handle));
DAQMX_ERR_CHK(CreateAiInputChannel(task_handle, config.channel.c_str(),
                                   config.channel_mode, config.min_voltage,
                                   config.max_voltage,
                                   config.accel_sensitivity_mv_per_g));
DAQMX_ERR_CHK(api.cfg_samp_clk_timing(
    task_handle, "", config.sample_rate_hz, DAQmx_Val_Rising,
    DAQmx_Val_ContSamps,
    static_cast<uInt64>(config.samples_per_read * 10)));
DAQMX_ERR_CHK(api.start_task(task_handle));

DAQMX_ERR_CHK(api.read_analog_f64(
    task_handle, config.samples_per_read, 10.0, DAQmx_Val_GroupByScanNumber,
    samples.data(), static_cast<uInt32>(samples.size()), &samples_read,
    nullptr));

Với mode voltage, bridge đọc điện áp trực tiếp. Với mode accel, bridge tạo kênh gia tốc bằng cấu hình sensitivity mV/g rồi trả dữ liệu đã mang ý nghĩa gia tốc.

Dữ liệu trả về Flutter gồm gì

Loại dòng Ý nghĩa
STREAM_STARTED Thông báo bridge đã bắt đầu stream thành công.
DATA_MULTI RMS của từng kênh theo block đọc hiện tại.
FFT_MULTI Phổ tần số của từng kênh để hiển thị FFT.
WAVE_MULTI Mẫu waveform đã decimate để vẽ dạng sóng.
ERROR Lỗi bridge hoặc lỗi DAQmx khi tạo task, start task, hoặc đọc dữ liệu.

Khi nào app không nhận được dữ liệu thật

Trên Windows, các nguyên nhân phổ biến không phải do thiếu cdaq9181_console.exe, mà thường là do một trong các lỗi sau.
  1. Máy chưa cài NI-DAQmx runtime x64 nên không nạp được nicaiu.dll.
  2. Thiết bị cDAQ chưa online hoặc Windows không nhận thiết bị.
  3. Channel cấu hình sai, ví dụ sai tên device prefix.
  4. Chế độ app đang là demo/mock thay vì bridge.
  5. Tham số sample rate, sample count, min/max không hợp lệ.

Ghi nhớ thực tế cho repo này

Trong workspace hiện tại, cấu hình phần cứng đã từng ghi nhận rằng prefix đúng là cDAQ9181-1E439C1Mod1/aiX. Nếu dùng sai device id, bridge có thể start nhưng task DAQ sẽ lỗi.

Vì vậy khi debug, cần kiểm tra theo thứ tự: runtime NI-DAQmx, thiết bị online, tên channel, rồi mới tới logic Flutter UI.
